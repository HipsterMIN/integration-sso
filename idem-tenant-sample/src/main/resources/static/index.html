ℹ 유관기관 OIDC 연동 흐름

설계서 §14~16장 기반 — 이 시뮬레이터가 재현하는 3단계 흐름

┌─────────────────────────────────────────────────────────────────────────────┐ │ 실제 유관기관 연동 전체 흐름 (E2E) │ │ │ │ [사용자] → QIM (Q-IM) 인증 완료 │ │ │ │ │ ▼ │ │ [IdO FE] ← GET /api/v1/fe-session/... (Keycloak 세션 확인) │ │ [IdO] → POST /api/v1/handoff/issue ← ① 기관이 Ticket 요청 │ │ Headers: X-Agency-Code, X-Agency-Key ← IdO 인터셉터 검증 │ │ Body: { qimUserId, authLevel, providerCode, ... } │ │ → HandoffTicket { ticketId, expiresAt } │ │ │ │ │ ▼ │ │ [기관] → POST /api/v1/handoff/verify ← ② Ticket 소비 │ │ Headers: X-Agency-Code, X-Agency-Key (DB SHA-256 검증) │ │ Body: { ticketId } │ │ Resilience4j CB + Retry 적용 │ │ → HandoffPayload { APPROVED | REJECTED | HOLD } │ │ │ │ │ ▼ (APPROVED 만 계속) │ │ [기관] Session Fixation 방지 │ │ → 기존 AGSID 쿠키 DB 무효화 + 삭제 │ │ → AgencySessionService.createSession() │ │ 192-bit SecureRandom → rawAGSID │ │ DB 저장: SHA-256(rawAGSID) ← 원문 미저장 │ │ → AGSID 쿠키 (Secure/HttpOnly/SameSite=Strict) │ │ │ │ │ [기관앱] → GET /agency/entry/session (세션 유효성 확인) │ │ → DELETE /agency/entry/session (로그아웃) │ │ │ │ Webhook 수신 (Push): POST /api/v1/webhook/inbound │ │ HMAC-SHA256 서명 검증 + 타임스탬프 ±5분 │ │ 이벤트 유형: HANDOFF_REVOKED, SESSION_ADVISORY, MEMBER_WITHDRAWN, ... │ │ │ │ 이벤트 폴링 (Pull): GET /api/v1/events/poll │ │ 우선순위 기반 배달, 중복 배달 방지 │ └─────────────────────────────────────────────────────────────────────────────┘
