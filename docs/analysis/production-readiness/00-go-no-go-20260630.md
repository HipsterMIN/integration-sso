# OnePass 통합인증 — 운영 배포 가능성(GO/NO-GO) 평가

> **작성일** 2026-06-30 · **대상 브랜치** `shipster` · **평가 방법** 직접 빌드 검증 + 배포/보안/데이터 3축 코드베이스 조사
> **핵심 질문**: *이 프로젝트를 실제 서비스로 올릴 수 있는가?*

## 0. 최종 판정

> **조건부 NO-GO → 단계적 GO 경로.**
> 코드·보안·아키텍처는 **상당히 성숙**(전 모듈 테스트 그린, 보안 Critical 다수 코드 레벨 해소, 컨테이너화·Helm·관측성 구비). 막는 것은 *대형 결함*이 아니라 **남은 배포 파이프라인 + 운영 선결조건(시크릿·기관 데이터·외부연동)**이다. **파일럿(소수 기관) 출시는 단기(수주) 내 현실적**, 68개 기관 전면 서비스는 회원통합·기관 온보딩이 추가로 필요.

## 2. 블로커 카테고리

### A. 코드/패키징/파이프라인 (배포를 직접 막는 것)
| # | 블로커 | 상태 |
|---|---|---|
| A1 | q-authz Dockerfile/prod 프로파일/Helm 배선 누락 | ✅ **해소**(이번 세션) |
| A2 | idem-support 빌드 red | ✅ **해소**(제거) |
| A3 | CI가 이미지 push 안 함 (`push:false`) | ✅ **해소** — GHCR push 전환(`ci.yml`) |
| A4 | 자동 배포 파이프라인 부재 | 🟡 **부분** — `cd.yml`(수동 Helm, KUBE_CONFIG 게이트) 추가. GitOps 채택 시 대체 |
| A5 | NICE/OACX 빈값 → 본인인증 무음 비활성 | ✅ **해소** — `AuthCredentialsValidator`(prod fail-fast) |

### B. 운영 선결조건 (코드는 완료, 설정/데이터만)
- **암호/시크릿**(미설정 시 의도된 기동 차단): `IDO_HANDOFF_AES/HMAC_KEY`, `QIM_CI_AES_KEY_V1`, `QIM_DI_SECRET`, `KEYCLOAK_CLIENT_SECRET`, `IDO_WEBHOOK_SIGNING_SECRET`, 내부 API 키, `AUTHZ_INTERNAL_API_KEY`, `NICE_CLIENT_*`/`OACX_PROVIDER_KEY_PATH`
- **기관 데이터**: `agency_meta`(최대 68개)·`callback_whitelist`·`SECRETS_AGENCY_*_API_KEY`·`REACT_APP_REDIRECT_ALLOWED_ORIGINS`·`ALLOWED_URL_*` — 현재 `AGENCY_STUB_001`만
- **인프라**: PostgreSQL/MariaDB HA, Redis, Kafka(3-broker), Vault(KMS), Keycloak
- **클러스터/CD**: `KUBE_CONFIG` 또는 GitOps(ArgoCD/Flux) 결정

### C. 단계적 출시로 미룰 수 있는 한계 (하드닝·후속)
- 보안 하드닝(문서상 잔여): Vault 토큰 자동 갱신(F5.3), audit `@Async` DB/Kafka 분리(F5.7), audit `actor_id` 가명화(F5.4)
- 통합테스트 환경(Testcontainers Docker) 정비, DLQ 전략(GAP-IDO-09), JTI replay 방지
- 연합 인가 다운스트림 컨슈머(회수 전파 루프 완성) — P2
- 동일인(소셜↔CI) 자동 통합 — `docs/member-integration-plan/` 참조(서비스 핵심, 단계적)
- 인프라 exporter(redis/kafka/pg) 모니터링 활성화

## 3. 영역별 준비도

| 영역 | 평가 | 근거 |
|---|---|---|
| 컨테이너화 | ✅ 양호 | 전 서비스 멀티스테이지 Dockerfile(비루트·레이어드 JAR·HEALTHCHECK). q-authz 추가 완료 |
| K8s/Helm | ✅ 양호 | `infra/helm/idem`(deployment/service/configmap/secret/hpa/pdb/networkpolicy). q-authz 배선 완료 |
| 운영 프로파일 | ✅ 양호 | 전 서비스 `application-prod.yml`(로그·actuator 최소노출). q-authz 추가 완료 |
| CI/CD | 🟡 부분 | CI(빌드·테스트·OWASP·Trivy·Sonar) 충실 + 이미지 GHCR push 추가. CD는 수동 템플릿(GitOps 결정 대기) |
| 보안(코드) | ✅ 양호 | KMS 가드, 시크릿 부팅검증(Sprint α/γ), Handoff AES-GCM+HMAC, 상수시간 비교, RLS 정의 |
| 데이터/마이그레이션 | ✅ 양호 | 모듈별 Flyway, 멀티DB 비-분산TX(아웃박스+멱등), V4 식별자 유니크 정합 |
| 관측성 | ✅ 양호 | Prometheus/Grafana/Loki + 알람 8종, actuator probe/메트릭 |
| 운영 선결조건 | ❌ 미충족 | 시크릿·기관데이터·외부연동·클러스터 미설정 |

## 4. 권고 출시 경로

```
[현재] 코드/패키징 정리 완료
   ↓  (수주, 엔지니어링)
B 운영 선결조건 충족(시크릿·인프라·기관 데이터) + CD 방식 확정
   ↓
파일럿 출시(협조 기관 1~수개) — 제한 범위
   ↓
C 하드닝(Vault 갱신·audit 분리/가명화·통합테스트·회수 컨슈머)
   ↓
기관 온보딩 웨이브 + 회원통합 → 전면 서비스
```

## 5. 운영 시크릿/환경변수 체크리스트 (요약)

```bash
# 암호키 (openssl rand)
IDO_HANDOFF_AES_KEY / IDO_HANDOFF_HMAC_KEY        # base64 32B
QIM_CI_AES_KEY_V1                                 # base64 32B (KMS)
QIM_DI_SECRET / IDO_INTERNAL_SIG_SECRET / IDO_WEBHOOK_SIGNING_SECRET  # hex 32
AUTHZ_INTERNAL_API_KEY  ( = IDO_QAUTHZ_INTERNAL_API_KEY )            # hex 32
QIM_INTERNAL_API_KEY    ( = IDO_QIM_INTERNAL_API_KEY )               # hex 32
# 외부연동
KEYCLOAK_CLIENT_SECRET / QSIGN_KEYCLOAK_CLIENT_SECRET
NICE_CLIENT_ID / NICE_CLIENT_SECRET / OACX_PROVIDER_KEY_PATH         # 미설정 시 prod 기동 차단
# 기관
agency_meta(+callback_whitelist) DB 적재 / SECRETS_AGENCY_*_API_KEY
REACT_APP_REDIRECT_ALLOWED_ORIGINS / ALLOWED_URL_*
# 인프라/CD
*_DB_HOST/USERNAME/PASSWORD, REDIS_*, KAFKA_SERVERS, VAULT_*, KUBE_CONFIG
```

> escape hatch(의도적 비활성): `ido.auth.allow-missing-credentials=true`(본인인증 미사용 배포)
