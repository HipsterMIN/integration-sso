# ADR-001: IdO 마이크로서비스 아키텍처 채택

| 항목 | 내용 |
|------|------|
| **ID** | ADR-001 |
| **제목** | IdO(Identity Orchestrator) 마이크로서비스 분리 아키텍처 채택 |
| **상태** | ✅ Accepted |
| **결정일** | 2025-Q4 (Sprint 1) |
| **결정자** | 아키텍처 위원회 |
| **관련 모듈** | ido, q-im, q-sign, agency-stub |

---

## 컨텍스트 (Context)

통합인증 플랫폼은 68개 이상의 기관 시스템과 연동하고, NICE 본인인증·OACX 간편인증·EzAuth 사업자 인증·Keycloak OIDC 등 다양한 IdP(Identity Provider)를 중개해야 한다. 초기 설계는 단일 Spring Boot 애플리케이션으로 모든 기능을 처리하는 모놀리식 구조였으나, 다음 문제가 식별되었다.

- **배포 결합도**: 인증 로직 변경 시 회원 정보 서비스까지 재배포 필요
- **확장성 한계**: 로그인 피크 트래픽과 회원 등록 트래픽이 서로 다른 스케일링 요구
- **장애 전파**: 기관 HTTPS 발송 실패가 로그인 요청에 영향
- **팀 경계 불명확**: 인증 담당·회원 담당·기관 연동 담당 코드가 혼재

---

## 결정 (Decision)

플랫폼을 **4개의 독립 Spring Boot 서비스**로 분리한다.

```
┌──────────────────────────────────────────────────────────┐
│               OnePass 마이크로서비스 구성                   │
│                                                          │
│  ┌─────────────┐    ┌──────────────┐    ┌─────────────┐ │
│  │  Q-Sign     │    │    IdO       │    │   Q-IM      │ │
│  │  :8081      │◄──►│   :8083     │◄──►│   :8082     │ │
│  │ Auth Session│    │Orchestrator  │    │Identity Mgr │ │
│  └─────────────┘    └──────┬───────┘    └─────────────┘ │
│                            │                             │
│                     ┌──────▼───────┐                    │
│                     │ Agency-Stub  │                     │
│                     │   :8090      │                     │
│                     │ PoC 기관 스텁│                     │
│                     └──────────────┘                     │
└──────────────────────────────────────────────────────────┘
```

### 각 서비스 책임

| 서비스 | 포트 | 책임 |
|--------|------|------|
| **Q-Sign** | 8081 | 인증 세션 생성·검증, OIDC Discovery, PKCE, Keycloak 콜백 |
| **IdO** | 8083 | 인증 오케스트레이션, Handoff 발급, 기관 Gateway, 프로비저닝, 감사 |
| **Q-IM** | 8082 | 회원 정보 CRUD, CI 암호화, 전환 세션, 동의 관리 |
| **Agency-Stub** | 8090 | PoC용 가상 기관 시스템 (Webhook 수신, Handoff 처리) |

### 서비스 간 통신 전략

- **동기**: REST/HTTP (Q-Sign ↔ IdO, IdO ↔ Q-IM)
- **비동기**: Apache Kafka (Q-IM → `qim.user.events` → IdO 소비)
- **결합 최소화**: 서비스 간 직접 DB 공유 금지 — 각 서비스 전용 PostgreSQL 스키마

---

## 결과 (Consequences)

### 긍정적 효과
- 서비스별 독립 배포 및 스케일 아웃 가능
- 장애 격리: 프로비저닝 실패가 로그인에 영향 없음 (Outbox 패턴 참고: ADR-008)
- 팀별 코드 오너십 명확화
- 각 서비스 독립 Flyway 마이그레이션 (충돌 없음)

### 부정적 효과 / 트레이드오프
- 분산 트랜잭션 복잡성 증가 → Transactional Outbox로 완화 (ADR-008)
- 서비스 간 네트워크 지연 추가 (~1ms per hop, 허용 범위)
- 로컬 개발 환경에서 4개 서비스 동시 기동 필요 (docker-compose 제공)
- 서비스 디스커버리: 현재 정적 URL 설정 (Phase 2에서 K8s Service DNS 전환 예정)

### 포기한 대안
- **모놀리식 유지**: 초기 개발 속도 빠르나 장기 유지보수·확장 불가
- **2-tier 분리(인증/회원)**: 기관 연동 규모 고려 시 불충분
